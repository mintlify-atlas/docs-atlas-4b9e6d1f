---
title: "What are DevPod providers? Docker, Kubernetes, and cloud VMs"
description: "Providers are plugins that tell DevPod how to create and manage developer environments — from local Docker containers to cloud VMs on AWS, GCP, Azure, and more."
---

Providers are the backbone of DevPod's flexibility. Each provider is a plugin that tells DevPod how to create, connect to, and manage a workspace — whether that means spinning up a local Docker container, scheduling a Kubernetes pod, or provisioning a virtual machine in a cloud provider. Providers are defined by a `provider.yaml` manifest that specifies the options, binaries, and commands DevPod needs to manage the full workspace lifecycle.

## Provider types

There are two distinct categories of providers depending on how they handle the underlying compute.

<CardGroup cols={2}>
  <Card title="Non-machine providers" icon="container">
    Work directly with containers rather than VMs. DevPod runs the workspace container on the target without creating or managing any virtual machine. Examples include the Docker, Kubernetes, and SSH providers.
  </Card>
  <Card title="Machine providers" icon="server">
    Create and manage a full virtual machine for each workspace. DevPod handles the complete VM lifecycle — provisioning, starting, stopping, and deleting. Examples include AWS (EC2), GCP, Azure, and DigitalOcean.
  </Card>
</CardGroup>

## Built-in providers

DevPod ships with three providers that are available without any additional installation:

| Provider | Type | Description |
| --- | --- | --- |
| `docker` | Non-machine | Runs workspace containers using a local or remote Docker daemon |
| `kubernetes` | Non-machine | Schedules workspace pods on any Kubernetes cluster |
| `pro` | — | Connects to a DevPod Pro or Loft instance |

## The provider.yaml manifest

Every provider — built-in or community — is defined by a `provider.yaml` file. This manifest declares the provider's name, version, configurable options, and the shell commands DevPod must run to manage the workspace.

```yaml
name: docker
version: v0.0.1
description: DevPod on Docker
options:
  DOCKER_PATH:
    description: The path where to find the docker binary.
    default: docker
  DOCKER_HOST:
    description: The docker host to use.
  INACTIVITY_TIMEOUT:
    description: "Automatically stop the container after the inactivity period. Examples: 10m, 1h"
  DOCKER_BUILDER:
    description: The docker builder to use.
exec:
  command: |-
    "${DEVPOD}" helper sh -c "${COMMAND}"
```

Options declared in `provider.yaml` are presented to you when you run `devpod provider add`, and can be reconfigured at any time using `devpod provider use` or `devpod provider set-options`.
