## Why DevPod?

DevPod reuses the open [DevContainer standard](https://containers.dev/) — the same standard used by GitHub Codespaces and VS Code Dev Containers — so your environment definition works everywhere.

## How it works

DevPod acts as the glue between your local IDE and the machine where you want to develop. You define your environment once in `devcontainer.json`, then DevPod spins it up on whatever backend you configure — locally with Docker, on a Kubernetes cluster, or on a cloud VM.

<Steps>
  <Step title="Install DevPod">
    Download the desktop app or install the CLI for your operating system.
  </Step>
  <Step title="Add a provider">
    Connect DevPod to Docker, Kubernetes, AWS, GCP, Azure, or any SSH-reachable machine.
  </Step>
  <Step title="Start a workspace">
    Point DevPod at a Git repository or local folder. It reads the `devcontainer.json` and builds the environment.
  </Step>
  <Step title="Open your IDE">
    DevPod automatically opens VS Code, a JetBrains IDE, or any configured IDE connected to the running container.
  </Step>
</Steps>

## Key features

- **Prebuilds** — pre-build workspace images to skip setup time on every `devpod up`
- **Dotfiles** — automatically clone and install your dotfiles into every workspace
- **Credential sync** — Git and Docker credentials are injected into the container automatically
- **Inactivity timeout** — containers shut down automatically after a configurable idle period
- **Desktop app** — manage workspaces, providers, and settings through a polished GUI
- **Extensible providers** — write custom providers for any infrastructure using a simple `provider.yaml`
