---
title: "Credential injection in DevPod: Git, Docker, and GPG"
description: "DevPod automatically injects Git credentials, Docker registry credentials, and GPG keys into every workspace so you can push code and pull images without manual setup."
---

DevPod automatically makes your local credentials available inside development containers through credential helpers and agent forwarding. This means you can push to private Git repositories, pull from private Docker registries, and sign commits with GPG — all without configuring credentials manually inside each workspace.

## Git credentials

DevPod injects HTTPS Git credentials into the container through a [git credential helper](https://git-scm.com/docs/gitcredentials). SSH credentials are forwarded automatically via SSH agent forwarding, which DevPod configures in the workspace SSH config.

This means `git push` and `git pull` work inside the workspace using the same credentials you have configured on your local machine, with no additional setup required.

To disable Git credential injection for all workspaces:

```bash
devpod context set-options default -o SSH_INJECT_GIT_CREDENTIALS=false
```

## Docker credentials

DevPod injects Docker registry credentials into the container through a [Docker credential helper](https://docs.docker.com/engine/reference/commandline/login/#credential-helpers). This allows you to pull and push images from and to private registries from within the workspace, using the same `docker login` credentials you have on your local machine.

To disable Docker credential injection for all workspaces:

```bash
devpod context set-options default -o SSH_INJECT_DOCKER_CREDENTIALS=false
```

## GPG agent forwarding

DevPod can forward your local GPG agent into the workspace through an SSH tunnel. This allows you to sign Git commits from inside the workspace using your existing GPG keys.

GPG forwarding is not enabled by default. To enable it for all workspaces:

```bash
devpod context set-options default -o GPG_AGENT_FORWARDING=true
```

To enable it for a single workspace:

```bash
devpod up my-workspace --gpg-agent-forwarding
```

You can also enable GPG agent forwarding for an existing SSH session:

```bash
devpod ssh my-workspace --gpg-agent-forwarding
```

## SSH agent forwarding

SSH agent forwarding is enabled by default in `devpod ssh`, which means your local SSH keys are available inside the workspace for operations such as authenticating with remote servers:

```bash
devpod ssh my-workspace
# SSH keys are forwarded by default (--agent-forwarding=true)
```

To disable SSH agent forwarding for a specific session:

```bash
devpod ssh my-workspace --agent-forwarding=false
```

## Summary

| Credential type | Default behavior | How to disable |
|---|---|---|
| Git HTTPS credentials | Injected automatically | `SSH_INJECT_GIT_CREDENTIALS=false` |
| Docker registry credentials | Injected automatically | `SSH_INJECT_DOCKER_CREDENTIALS=false` |
| SSH keys | Forwarded via agent (in `devpod ssh`) | `--agent-forwarding=false` |
| GPG keys | Not forwarded by default | `GPG_AGENT_FORWARDING=true` to enable |
